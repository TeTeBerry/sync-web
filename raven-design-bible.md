# Raven Design Bible

Raven is an immersive AI Festival Companion.

This document defines how Raven should feel, look, move, and behave across every page.

Raven should never feel like a dashboard, admin panel, database, or generic AI SaaS product.

---

# 1. Brand

## Mission

Raven helps festival lovers discover festivals, understand lineups, and plan unforgettable festival journeys with AI.

Raven is not just a tool.

Raven is the emotional bridge between:

- discovering a festival
- imagining the trip
- understanding the music
- planning the journey
- eventually going there

## Brand DNA

Raven should feel:

- immersive
- premium
- cinematic
- intelligent
- minimal
- emotional
- music-first
- travel-aware
- future-facing

## Brand Positioning

Raven is:

> The world's most beautiful AI Festival Companion.

Raven is not:

- an event listing site
- a travel booking site
- an AI dashboard
- a festival database
- a management tool
- a generic SaaS app

## Emotional Promise

Users should feel:

> “I’m not just browsing an event. I’m entering a festival journey.”

The product should create anticipation before it creates utility.

# 2. Visual Language

## Core Principle

Do not build sections.

Build scenes.

Every page should feel like a sequence of cinematic scenes, not stacked UI blocks.

## Layout

Use:

- full-width scenes
- large hero moments
- editorial spacing
- immersive imagery
- asymmetrical rhythm
- strong visual hierarchy
- generous whitespace

Avoid:

- dense grids
- repeated cards
- bordered boxes everywhere
- form-like layouts
- dashboard-style modules
- generic SaaS spacing

## Typography

Typography should feel editorial and premium.

Use:

- oversized headlines
- short subtitles
- minimal body text
- strong contrast between headline and details
- calm, confident language

Avoid:

- long paragraphs
- too many labels
- small text-heavy cards
- dashboard-style microcopy

Preferred rhythm:

```text
Huge emotional headline

Short atmospheric sentence

Small useful metadata
```

## Color

Base Raven palette:

- deep black
- midnight navy
- violet
- electric blue
- soft white
- muted gray

Use gradients as atmosphere, not decoration.

Avoid using purple/blue everywhere in the same way.

Each festival should influence the page atmosphere.

## Imagery

Imagery should feel like:

- music
- travel
- anticipation
- night
- light
- movement
- scale

Avoid:

- generic stock photos
- cheesy party photos
- overused AI graphics
- fake futuristic dashboards
- random neon decoration

## UI Density

Raven should feel spacious.

Information should appear progressively.

If everything is visible at once, the page becomes a dashboard.

---

# 3. Motion

## Motion Principle

Motion should guide emotion and attention.

Motion should never exist only to show off.

Use motion to make Raven feel alive.

## Preferred Motion

Use:

- slow hero zoom
- subtle parallax
- fade and rise reveals
- atmospheric gradients
- soft glow movement
- lightweight particles
- hover depth
- smooth scene transitions

Avoid:

- aggressive animations
- scroll hijacking
- long loading screens
- excessive 3D
- distracting effects
- animation that blocks reading

## Timing

Recommended timing:

- hover: 150–250ms
- small reveal: 300–500ms
- scene transition: 500–900ms
- background movement: slow and continuous

Motion should feel calm, not hyperactive.

## Page Transitions

Moving from page to page should feel like continuing the same journey.

Home → Events → Event Detail → Plan should not feel like entering different products.

# 5. Page Philosophy

## Homepage

Purpose:

Build anticipation.

The homepage should sell the Raven world.

It should feel like an invitation.

Do not overload it with product details.

Homepage structure:

```text
Hero Scene
↓
Festival Discovery Promise
↓
AI Journey Preview
↓
Music + Travel Intelligence
↓
Final CTA
```

## Events Page

Purpose:

Build discovery.

Events is not a database.

Events should feel like exploring possible futures.

The user should think:

> “Where do I want to go next?”

Events structure:

```text
Featured Festival Scene
↓
Festival Collection
↓
Discover by Mood
↓
Festival Season Timeline
```

Avoid:

- plain grids
- too many filters
- database-like cards
- generic event listing UI

## Event Detail Page

Purpose:

Build excitement.

Event Detail is not a wiki page.

It should make the festival feel alive.

The user should think:

> “I want to be there.”

Event Detail structure:

```text
Festival Hero Scene
↓
Festival Story
↓
Lineup as Centerpiece
↓
Raven AI Insights
↓
Travel Snapshot
↓
Generate Plan CTA
```

Lineup should be visually important.

The festival is the hero.

AI should support the experience, not dominate it.

## Plan Page

Purpose:

Build confidence.

Plan is not an AI report.

Plan is the user’s festival journey.

The user should think:

> “This trip feels possible.”

Plan structure:

```text
Journey Hero
↓
Journey Timeline
↓
Music Plan
↓
Stay Recommendation
↓
Budget Confidence
↓
Travel Checklist
↓
Final CTA
```

Music comes before stay so the festival remains the emotional center of the journey.
Stay and logistics follow once the nights feel real.

Avoid:

- report layout
- dashboard modules
- scattered cards
- too many equal-weight sections

## Future Booking Page

Purpose:

Build commitment.

Booking should feel clear and trustworthy.

This page can be more functional, but it should still feel like Raven.

Use emotion less, clarity more.

# 6. Components / Design Primitives

Raven should not rely on generic SaaS components.

Prefer design primitives that express story and atmosphere.

## Hero Scene

Used for:

- Homepage
- Events featured festival
- Event Detail
- Plan intro

Rules:

- large
- cinematic
- minimal text
- one primary action
- strong atmosphere
- festival-specific theme when possible

## Festival Poster

Used for:

- event discovery
- festival collections
- related festivals

Rules:

- visual-first
- large title
- date and location
- minimal metadata
- no dense badge clusters

## Editorial Block

Used for:

- festival story
- AI insights
- travel context
- music explanation

Rules:

- short copy
- large typography
- no dense paragraphs
- feels like a magazine, not a product manual

## Artist Spotlight

Used for:

- lineup
- recommendation
- music plan

Rules:

- artist name should feel prominent
- genre and reason should be secondary
- AI insight should be short and useful
- avoid spreadsheet-style artist lists

## Journey Timeline

Used for:

- Plan page
- travel flow
- festival itinerary

Rules:

- timeline is emotional, not just logistical
- show progression
- make the trip feel achievable
- reduce scattered travel cards

## Travel Story

Used for:

- airport
- hotel
- shuttle
- local movement
- stay area

Rules:

- explain why it matters
- prioritize clarity
- avoid booking-comparison UI
- use one primary recommendation first

## Budget Confidence

Used for:

- Plan page
- cost estimate
- trip feasibility

Rules:

- one big number
- simple breakdown
- clear confidence level
- avoid complex finance UI

## Immersive CTA

Used for:

- Generate Plan
- Join Waitlist
- Export Calendar
- Browse Festivals

Rules:

- strong but calm
- visually integrated into the scene
- never looks like a generic SaaS button cluster

---

# Final Design Test

Before shipping any Raven page, ask:

1. Does this feel like Raven?
2. Does this feel like a festival journey?
3. Does this avoid dashboard patterns?
4. Is the festival the hero?
5. Is the AI helpful but not visually dominant?
6. Would a user remember this page tomorrow?

If the answer is no, redesign it.
